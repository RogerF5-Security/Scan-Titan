# Scan Titan 22.3.0 — Servicios y acceso sin credenciales

- Auditoría FTP: login anónimo, listado de directorio y disponibilidad de AUTH TLS.
- Auditoría SMB: sesiones nulas/Guest, recursos listables sin contraseña,
  identificación anunciada del servidor/SO, SMB1 y firma de mensajes.
- Alternativa Nmap SMB1 para Windows cuando Impacket no está disponible;
  backend Impacket para SMB1/2/3. Cobertura parcial explícita por backend.
- Perfil NSE SMB con detección específica MS17-010, modos de autenticación,
  protocolos y firma. Parser de resultados `hostscript` y controles negativos.
- IDOR con objetos y propietarios conocidos; autenticación ausente basada en
  contenido protegido y referencia autenticada.
- RCE mediante dos resultados aritméticos distintos; SSRF con cuerpo de prueba
  controlado, dos respuestas y rechazo de reflejos/redirecciones.
- Corrección de parámetros HTTP duplicados que impedían sustituir el valor probado.
- HTTP 200 en rutas administrativas queda como candidato informativo hasta tener prueba.
- Objetivos sin respuesta HTTP continúan con infraestructura y omiten pruebas web.
- Procesos de servicio acotados y cobertura conservada ante errores/dependencias ausentes.

## Configuración y límites

FTP/SMB se revisan automáticamente en sus puertos habituales. Se pueden añadir
puertos y nombres de recursos en `stateful.services`. IDOR necesita identidades
y reglas de acceso; SSRF visible necesita `stateful.ssrf.probes` o metadata cloud
habilitada explícitamente. No hay cobertura universal de RCE, SSRF ciego, MFA o
lógica de negocio. No se prueban escritura ni descarga de archivos FTP/SMB.

En Windows, `config/requirements-smb.txt` habilita opcionalmente Impacket; sin él,
la comprobación nativa de acceso se limita a SMB1 y recursos configurados.

Ver [cobertura y ejemplos](https://github.com/RogerF5-Security/Scan-Titan/blob/v22.3.0/docs/SERVICE_ACCESS.md) y
[configuración de perfiles](https://github.com/RogerF5-Security/Scan-Titan/blob/v22.3.0/config/stateful.example.yaml).
